# 9. Deploy the Lab 9 port on Azure instead of Google Cloud

- Status: accepted (amends ADR 0008)
- Date: 2026-11-11
- Lab: 9 (second cloud)

## Context

[ADR 0008](0008-gcp-port.md) chose the services for a GCP port, and `gcp/` implements it. Google
Cloud would not start the Free Trial for the author's payment method without a one-time $30
prepayment (refundable only by closing the billing account), and without a billing account Cloud
Run, Cloud SQL and Artifact Registry cannot be used. The instructor approved doing the lab's
"second cloud" part on **Azure** (Azure for Students: about $100 credit, no card). The question
of the lab, "what would it take to run the same system on another cloud, and what does it cost?",
is unchanged; only the cloud is.

`gcp/` stays in the repository, validated but never applied: it is the answer to the lab as
written, and the Azure module reuses its decisions. Part 4 (BigQuery, Looker Studio, Document AI)
is GCP-specific and is done as in the assignment where it needs no billing.

## Decision

Same split as ADR 0008: frontend, API and database move; Cognito, the weekly report and the agenda
parser stay on AWS. Terraform in [`azure/`](../../azure) (azurerm `~> 4.0`), own state in the HCP
Terraform workspace `new-project-azure` (Local execution).

### Service mapping

### Database

Azure Database for PostgreSQL Flexible Server, `B_Standard_B1ms` (1 vCore, 2 GiB), PostgreSQL 17,
32 GiB, public endpoint, TLS, password authentication. Options considered, as in ADR 0008:
Cosmos DB (a rewrite of the data layer, not a port) and keeping Aurora (cross-cloud latency and
egress) lose for the same reasons. The schema comes from the Alembic migrations that run when the
container starts, not from a `pg_dump`.

**Network exposure is the weak point.** The cheapest working setup is a public endpoint with the
"allow Azure services" rule (`0.0.0.0`), which admits *any* Azure customer's traffic to the
endpoint; only TLS and a 48-character random password protect it. Private networking (VNet
integration with a delegated subnet and private DNS) closes that, but Container Apps then needs a
VNet-integrated environment, which adds setup and, for a workload-profiles environment, cost.
Accepted for a lab database with test data; **not acceptable for real data**.

The password is generated by Terraform, written to Key Vault, and passed to the app as a
Key Vault reference; `app/config.py` builds `DATABASE_URL` (with `ssl=require`) from `DB_HOST`,
`DB_NAME`, `DB_USER`, `DB_PASSWORD`. It is also in the Terraform state (HCP encrypts it at rest).
The server's administrator is the application user: a separate least-privilege role would be the
next hardening step.

### E-mail

Unchanged: the report keeps SES, whose key is an IAM role on the AWS Lambda. If the sender ever
ran on Azure, the API key (SendGrid, or an ACS connection string) would live in Key Vault, read by
a managed identity, never in `.env`, the image or Terraform variables.

### Keys and identity

- Laptop: `az login`; the provider uses the CLI token. No client secret.
- The API: a user-assigned managed identity, `AcrPull` + `Key Vault Secrets User`, nothing else.
- Terraform needs rights to create role assignments (Owner, or Contributor + User Access
  Administrator, on the resource group); Azure for Students gives the account owner that. A
  narrower custom role is the production answer.
- The only token that leaves Azure is the Static Web Apps **deployment token**, which
  `azure/deploy.sh` reads from Azure for one upload and does not store. Rotating it is one
  command; deploying through GitHub Actions with OIDC federation would remove it.

## Alternatives considered

| Alternative | Why it lost |
|---|---|
| **Pay GCP's $30 prepayment** | Refundable only by closing the billing account; the author chose not to. |
| **Submit `gcp/` as written, not deployed** | Satisfies the form but proves nothing: no URL, no measured cost. Azure was approved. |
| **App Service (Linux, B1) for the API** | ~$13/month always on, no scale to zero. |
| **Azure Container Instances** | Bills while running; no scale to zero, no HTTPS ingress without more parts. |
| **Static Web Apps Standard with a linked backend** | Removes the CORS setup but costs ~$9/month for no other benefit in this lab. |
| **GHCR/Docker Hub instead of Container Registry** | Saves $5/month. Container Apps could pull from GitHub's registry with a token; we would be creating exactly the long-lived pull secret that managed identity avoids. Revisit if the $5 matters. |

## Consequences

- The database never sleeps and the idle bill is about **$8.70/month stopped, $21/month running**
  against ≈ $0.30 on AWS (figures and the four profiles: [`docs/lab9-report.md`](../lab9-report.md)).
  Of the stopped bill, $5 is the registry and has nothing to do with the database.
- A stopped server comes back by itself after 7 days: "stopped" is not a state you can forget.
- Cognito's callback URLs and the parser's CORS origins need the Static Web Apps address added to
  `app_urls` in `infra/terraform.tfvars` before sign-in works there.
- `ignore_changes` on the Container App's image: Terraform owns the shape, `azure/deploy.sh`
  owns the code (the two roads of ADR 0007).
